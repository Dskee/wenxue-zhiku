# 评测数据集变更记录

规则：样本的新增、删除、标注修改都必须在这里记一条，并同步更新 `version` 与 md5。
报告里引用数据集时要带「版本 + md5」，否则两次报告的数字不可比
（`eval/run_ablation.py` 会把两者自动写进报告的「设置」小节）。

## v1.0 — 2026-10-27

- 规模：40 条，`normal` 24 / `boundary` 8 / `no_answer` 8。
- 数据集 md5：`559d14690bb7338048021235f28019f7`（文件 `eval/dataset/v1.0.jsonl`）。
- 语料：`agent面试问答.md`（489 chunk，私有笔记，不提交）+ `唐诗三百首.md`
  （385 chunk，公版，已提交在 `eval/corpus/`），合计 874 chunk（871 个不同正文）。
- 题目分布：n01–n14 Agent 工程问答（RAG/记忆/Agent 架构/MCP/部署）；n15–n24 唐诗
  （其中 4 条是「描述场景→是哪首诗/哪一句」的改写题，不是纯填空）；b01–b08 边界题
  （需要跨段综合、或两种说法取舍）；x01–x08 拒答题（语料里确实没有的内容）。
- 标注方式：`eval/dataset/specs/v1.0.json` 里逐字摘答案片段当作 `evidence`，由
  `eval/tools/build_dataset.py` 归一化后反查内容寻址的 chunk id 生成 `v1.0.jsonl`。
  这样做的好处是**语料一改，构建就会失败**，标注不会悄悄漂移；同时构建脚本会检查
  「问题是否直接抄了原文」（与语料的最长公共子串 ≥40 字直接报错，≥20 字告警）。
- 多 gold 样本：n17（《登鹳雀楼》在语料里还有一个错字版《登鹤雀楼》）、b01（同一段
  答案跨两个块）。指标按 gold 集合计算，不是只认第一个。
- 已知局限：
  - 语料里的唐诗是繁体/异体字版本，标准写法（「滚滚来」「猿啸哀」「黄鹤去」）在库里
    匹配不到，出题一律按语料原文写；《望庐山瀑布》不在语料中。
  - 私有笔记部分 CI 复现不了，CI 只跑 `gold_source == 唐诗三百首.md` 的子集。
  - 40 条是「够用」而不是「统计学显著」；单次运行的生成层有抖动，趋势比绝对值可靠。
